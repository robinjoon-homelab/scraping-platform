# Agent Docs 실버 데이터 연동

## 범위와 결정

Agent Docs 요구 정의 v15(2026-11-16) F8-1~F8-5를 기준으로 한다. 이 저장소는 수집 설정·원본 JSON 응답 묶음·실행 이력·계획 범위의 실버 레코드 export를 소유한다. Agent Docs는 스페이스의 수집 연결·가공 지침 문서·pending 목록·ingest_pending/ingest_done·문서·리비전·출처 칩·처리 기록을 소유한다. 요약·LLM·문서 모델은 추가하지 않는다.

이번 서버 계약은 Bearer 인증 pull이다. push 대상 URL·외부 토큰은 저장하지 않는다. 실제 Agent Docs 전송 선택은 미확정이며 수신기와 이 pull 계약의 채택·연결은 후속 작업이다. 외부 시스템 호출이나 배포는 수행하지 않는다.

## 공개와 재개

관리자는 계획별 pull 허용을 저장한다. 기본값은 비활성이다. 0부터 읽는 피드가 기존 성공 레코드 전체를 점진적으로 포함하므로 별도 초기 목록의 불안정한 최대 DB ID 경계를 사용하지 않는다. 페이지 한도는 1~100, 기본 20이며 각 payload의 기존 최대 크기는 1,000,000자다. 레코드를 개별 기사로 해석하지 않는다.

피드 요청은 단일 공개 카운터 행을 잠근 뒤, 아직 공개하지 않은 커밋된 SUCCEEDED 레코드를 최대 요청 한도만큼 찾아 공개 원장에 추가한다. 원장과 카운터는 같은 트랜잭션에서 확정된다. 미커밋 레코드는 선택되지 않고 다음 요청에서 다시 발견되며 ID·시각이 작아도 누락되지 않는다. 원장에는 원본 record ID와 불변 순번을 보존하므로 동일 after의 재전달이 같은 레코드를 가리킨다. 계속 추가되는 피드는 이후 페이지에서 새 레코드를 더 포함할 수 있다.

계획 ID가 범위이며 이름·일정 변경은 범위를 바꾸지 않는다. 각 항목에 저장 레코드 ID, 출처 ID·원천 키·내용 해시·schemaVersion·payload·수집/원천 수정 시각·실행 ID와 실행 당시 계획/출처 스냅샷·설정 버전을 포함한다. 계획별 중복 억제는 동일 출처를 쓰는 다른 계획을 누락하지 않는다. 기존 데이터는 확인 가능한 최초 관측만 보존하며 과거 누락 관측은 생성하지 않는다.

`nextAfter`는 마지막 반환 공개 순번이다. 빈 페이지는 입력 위치를 유지하며 소비자는 이 위치로 다시 poll한다. after는 음수나 계획의 공개 위치보다 큰 값을 허용하지 않는다. 순번에는 다른 계획 때문에 빈 구간이 있을 수 있다. 자동 삭제·만료는 없으며 범위 변경이나 보존 삭제는 별도 계약 없이 수행하지 않는다. 빈 페이지를 원천 삭제 증거로 사용하지 않는다.

## 상태와 소비자 책임

설정과 공개 레코드 수·마지막 공개 순번은 DB에서 저장/파생한다. pull 성공은 소비자 처리 완료가 아니다. 서버는 ack나 processed 성공을 만들지 않는다. 소비자는 마지막으로 안전하게 반영한 공개 순번을 자기 저장소에 보관한다. 이 위치는 원천 체크포인트와 독립이다.

Agent Docs 수신기는 연결별 `(sourceId, sourceRecordKey, revisionHash)` 중복을 억제하고 pending 저장과 자기 수신 위치를 원자적으로 확정해야 한다. 에이전트의 가공과 ingest_done 멱등 키·만든 리비전·행위자·처리 시각은 Agent Docs가 구현한다. 실패한 가공은 수집 성공을 취소하지 않는다. 수신기 구현·실제 전송 선택·운영 연결·종단 간 검증은 남아 있다.

정확한 HTTP 요청·응답은 생성되는 REST Docs를 원본으로 한다.
